# Security Policy

## Reporting a vulnerability

Before publishing this template, replace this paragraph with a monitored private reporting address or enable GitHub private vulnerability reporting. Do not report suspected vulnerabilities in public issues.

When reporting, include the affected file or skill, a clear reproduction, impact, and any suggested mitigation. Please avoid including real secrets, production payloads, or personal data.

## Scope

Security issues include guidance that could encourage unsafe FFI, accidental secret exposure, unsafe handling of sensitive data, authorization or transaction bypasses, or a path that makes a host process crash or behave insecurely.

Maintainers should acknowledge reports promptly, assess impact, and coordinate a fix before public disclosure where practical.
